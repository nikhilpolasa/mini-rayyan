# Mini Rayyan design decisions

## Release summary

Maintainer-approved Phase A now adds search threads: each topic has its own query history and version counter inside the configured database. Judgment isolation is not part of Phase A. The original four blockers were criteria initialization, query-dependent screening reuse, decision-button refresh and incomplete acceptance coverage. Their code fixes are committed: missing defaults are inserted without re-enabling reviewer-disabled criteria; cache keys include query concepts, criteria, content and rule version; stale in-flight reads are cancelled before refresh; and the isolated ten-step API acceptance harness passes. Phase A passed **387 backend tests, 25 frontend tests and the production build**. Backups and migration were exercised only on isolated test databases; the live database was not migrated in this task. These are automated results, not proof of interactive browser acceptance or medical accuracy.

Before release, complete the browser/CSV-in-Excel checks, verify judge-accessible deployment and persistent database configuration, and finish the report/demo evidence. The exact original browser session was not reproduced; a refresh race was independently reproduced and fixed. Do not assume that this docs task restarted the app or changed any populated database.

**Scope is decided:** the maintainer has superseded the earlier E7/CC2 exclusion with scoped Phase A. Projects are search-thread metadata only; New search starts v1, Revise adds a version, and legacy history remains untouched in project 1. Judgments, human PICO, criteria and global duplicate visibility remain shared (M3). Phase B is explicitly not implemented, so separate databases remain the operational isolation workaround. F7 is the tested simple related-report guard. G5 adds no age exclusion: child-only or unclear age is Maybe for manual review; automatic age routing is not implemented/verified. H1 is the tested post-commit, separate-transaction PICO trigger after a human record Include. CC7 is only optional query_id on record detail/export, with matching frontend cache keys; no run selector or schema change.

**Deferred and open:** CC3-CC6 stay after v1.0; CC1 is minimal warning display only after the blocker fixes, not a diagnostics/schema project. True OPEN items are official deadlines, organizer contact/Scoring Metrics/snapshot/access/submission details, team eligibility, any extra exclusions, quality gates, annotator availability and hosting readiness. Deferred implementation is a DECIDED scope choice, not an unresolved release requirement. The demo plan is 300 seconds including reserve. DECIDED never means untested behaviour is verified.

Prepared 28 October 2026 against `agents.md`, `docs/PRD.md`, `docs/design-questions.md`, the official `Track1_PS.pdf`, the inspected implementation and the latest user requests. This is a design review, not a claim that every proposed behaviour is implemented. No application code is changed by this document. The final report's three-page limit does not apply to this question-by-question decision register.

**DECIDED** means a safe design default within the existing scope; it does not mean implemented or verified. **OPEN** means a human, maintainer or organizer must settle the specified choice. A **CONTRACT CHANGE** is a proposed signature, API or schema extension and is not authorized for implementation by writing it here. Each Answer explicitly states its contract impact. Non-functional logistics without a requirement ID cite the relevant PRD section instead of inventing an ID.

Prior baseline verification at commit `6fcea05` passed 376 backend and 22 frontend tests. Current Phase A verification passed 387 backend and 25 frontend tests plus the production build. The earlier live workflow persisted three unique papers from 378 hits with cap three and demonstrated reuse. The blocker fixes and approved small changes are covered by automated tests. Phase A tests were run against isolated databases and mock source data; no full browser, live PubMed or actual PostgreSQL run was performed. Browser acceptance, Excel opening, deployment/PostgreSQL and real-data accuracy remain unverified; the current populated live database was not inspected or changed.
